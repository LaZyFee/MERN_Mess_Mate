# MealMate engineering assessment

The Express API can support frontend integration work. A production accounting release still depends on proving that one month close sees one consistent set of inputs and that each approved expense credits the intended payer. These are release decisions because the API can return a valid-looking statement even when its business inputs differ from the approval record.

| Complete identity hardening | OTP setup uses an encrypted secret and process-local challenges. A development key fallback exists. Shopping conversion saves the expense and then closes the list. | A crash can leave an in-flight key or multiple drafts. | Couple state transition, result snapshot and source ID in one transaction. Reconcile stuck reservations and enforce a unique source on conversions. | Safe retries after disconnects. | High | Medium | IdempotencyRecord, shopping, recurring |

## Scalability and performance

Several list endpoints return whole arrays. | Longer histories increase close latency and memory use. | Benchmark 100 residents over 24 months. ## Prioritized roadmap

1. **Immediate** — resolve payer/guest policy, period atomicity, tenant references and session-family migration. Run a signed golden month before enabling live accounting.
2. **Short term** — add CI contract fixtures, outbox recovery, receipt quarantine and a clean-checkout deployment/restore rehearsal.
3. **Medium term** — benchmark group history, ship Bengali statement explanations and budget forecasts after ledger sign-off.
4. **Long term** — introduce shared socket/limiter state when a measured second-instance need appears. Pilot offline drafts after privacy review.
